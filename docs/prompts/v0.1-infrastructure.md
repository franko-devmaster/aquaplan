# AquaPlan v0.1 — Infrastructure

## Contexte

**Projet**: AquaPlan — Application web de gestion des analyses d'eau pour le Canton de Fribourg, Suisse
**Itération**: v0.1 — Setup technique et CI/CD
**Épic Jira**: AQ-1 "Setup technique & CI/CD"
**Durée estimée**: 8 sprints (39 sous-tâches)
**Repository**: francisuster/aquaplan (Bitbucket, branche Main)
**Jira**: chfr.atlassian.net/browse/AQ

### Stack technique

- **Backend**: .NET 10, C# latest, ASP.NET Core, Entity Framework Core, PostgreSQL, Serilog, OpenTelemetry
- **Frontend**: Angular 19, TypeScript 5.6, Angular Material, Bootstrap 5, ngx-formly, @ngx-translate
- **API**: NSwag (auto-génération clients TypeScript), Swashbuckle
- **Auth**: ASP.NET Identity, JWT, OIDC
- **Testing**: xUnit, FluentAssertions, Moq, MockQueryable.Moq
- **Containerization**: Docker, Docker Compose (dev), K8s (prod)
- **CI/CD**: Bitbucket Pipelines

### Conventions & Références

Tous les développements doivent respecter les conventions du fichier **`AquaPlan/CLAUDE.md`** du dépôt:
- Structure de la solution, nommage (PascalCase/camelCase), patterns d'architecture
- Conventions de tests (.NET obligatoires: xUnit + FluentAssertions + Moq)
- Règles de sécurité (authentification par défaut, validation input, tenant isolation)
- Patterns Angular (standalone components, signals, datastore, guards)

## Instructions de Travail

### Git & Commits

1. **Branches feature**: Créer une branche pour chaque histoire:
   ```bash
   git checkout -b feature/AQ-70-init-solution-dotnet
   ```

2. **Commits par sous-tâche**: Valider après chaque sous-tâche completée:
   ```bash
   git commit -m "AQ-88: Create solution structure with 6 projects

   - Created AquaPlan.sln with core projects
   - Added project references
   - Configured initial package references

   Jira: AQ-88"
   ```

3. **Messages de commit** (Conventional Commits + Jira):
   - Format: `<type>(<scope>): <subject>`
   - Types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`
   - Subject: impératif, sans point, 50 caractères max
   - Body: contexte, raison, Jira key
   - Exemple: `feat(api): configure ASP.NET Core pipeline (AQ-90)`

4. **Merge vers Main**: Une fois l'histoire complète:
   ```bash
   git checkout main && git pull
   git merge feature/AQ-70-init-solution-dotnet
   git push origin main
   ```

### Tests & Validation

1. **Tests .NET OBLIGATOIRES**: Chaque histoire avec du code .NET doit avoir des tests:
   - Minimum 1 test par sous-tâche fonctionnelle
   - Framework: xUnit + FluentAssertions + Moq
   - Nommage: `<MethodName>_Should<Expected>_When<Condition>` ou `<MethodName>_Should<Expected>`
   - Exécution: `dotnet test` doit passer à 100%

2. **Lint & Format**:
   - .NET: `dotnet format` (EditorConfig)
   - Angular: `ng lint` doit passer
   - Avant commit: vérifier `git status` pour les fichiers générés

3. **Build local**:
   - Avant de pousser: `dotnet build` (solution) + `ng build` (Angular)
   - Pas de warnings, erreurs acceptées seulement si documentées

### Mise à jour Jira (agent `jira-updater`)

Utiliser l'agent Claude Code **`jira-updater`** (`.claude/agents/jira-updater.md`) pour synchroniser les statuts :

1. **Démarrer l'itération** (à faire une seule fois au début) :
