## Contexte

**Projet**: AquaPlan — Application web de gestion des analyses d'eau pour le Canton de Fribourg, Suisse
**Itération**: v0.2 — Authentification & Rôles utilisateurs
**Épic Jira**: AQ-2 "Authentification & Utilisateurs"
**Durée estimée**: 2-3 sprints (14 stories, 45 story points)
**Repository**: francisuster/aquaplan (Bitbucket, branche Main)
**Jira**: chfr.atlassian.net/browse/AQ

### Base de v0.1

La v0.1 Infrastructure a mis en place:
- Solution .NET 10 avec 7 projets (Api, Web, Worker, Domain, Application, Infrastructure, Shared)
- PostgreSQL + EF Core avec DbContext initial (User, Tenant)
- Angular 19 standalone avec Material + Bootstrap
- Authentification skeleton: ASP.NET Identity, JWT handler, OIDC configuration
- AuthGuard et RequestInterceptor Angular
- CI/CD (Bitbucket Pipelines), Docker, Serilog, OpenTelemetry
- NSwag pour génération automatique clients TypeScript

**v0.2 construit sur cette fondation** pour implémenter l'authentification complète et un système de gestion des rôles avec permissions granulaires.

### Stack technique

- **Backend**: .NET 10, C# latest, ASP.NET Core, Entity Framework Core, PostgreSQL, Serilog, OpenTelemetry
- **Frontend**: Angular 19, TypeScript 5.6, Angular Material, Bootstrap 5, ngx-formly, @ngx-translate
- **Auth**: ASP.NET Identity (Identity Core), JWT, OIDC, Policy-based Authorization
- **Testing**: xUnit, FluentAssertions, Moq, MockQueryable.Moq
- **Containerization**: Docker, Docker Compose (dev), K8s (prod)
- **CI/CD**: Bitbucket Pipelines

### Conventions & Références

Tous les développements doivent respecter les conventions du fichier **`AquaPlan/CLAUDE.md`** du dépôt:
- Structure de la solution, nommage (PascalCase/camelCase), patterns d'architecture

- Règles de sécurité (authentification par défaut, validation input, tenant isolation, audit trail)
